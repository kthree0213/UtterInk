# Accessibility acceptance matrix

This document records the Task 8 Debug preflight. It is not release approval.
Every surface and state below is currently `BLOCKED` by the shared release-gate
gaps in B1. A Debug observation confirms only the behavior that was actually
exercised; it does not substitute for a run on the exact Release candidate.

## Acceptance rules

- Exercise the real menu, panels, windows, sheets, dialogs, and all pipeline
  states. Test with VoiceOver enabled and Full Keyboard Access enabled.
- Verify accessible name, role, value, enabled/disabled state, and actions;
  state and error announcements must be specific and must not disclose
  transcript text, provider keys, or other private content.
- Keyboard checks include logical traversal, a visible focus indicator, no
  keyboard trap, Escape/cancel behavior, and focus returning to the invoking
  control after a sheet, dialog, popover, or window closes.
- Icon-only controls require a non-empty, action-specific label. Status and
  error meaning must remain understandable without color.
- Normal text must meet at least 4.5:1 contrast. Large text and essential
  non-text controls/focus indicators must meet at least 3:1, unless a stricter
  native-system equivalent is documented with the evidence.
- Repeat appearance checks in Light and Dark mode, Increase Contrast,
  Differentiate Without Color, Reduce Motion, and the largest practical text
  and display scaling. Record clipping, overlap, truncation, and loss of action
  access as failures.
- Allowed row results are `PASS`, `FAIL`, or `BLOCKED`, with an evidence link or
  note. Blank or unset results do not pass the release gate.
