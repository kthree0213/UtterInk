# UtterInk 0.1.0 Finish Plan

Status: active

Product baseline: `5d18611df13c1bd2d03510b5e5a6cee3312dc5f3` on
`feature/utterink-implementation`

Goal: publish the existing UtterInk 0.1.0 scope as open source with a signed,
notarized, stapled, verified Apple Silicon DMG.

This is the execution plan for the remaining work. The earlier design and
implementation plans remain reference material, but they do not drive new
scope.

## Operating rules

- Do not add 0.1 features or redesign the current architecture.
- Use ordinary direct execution; do not invoke a Superpowers planning or
  execution workflow for the remaining work.
- Reuse the existing tests and release tooling; do not add another planning,
  evidence, or hardening framework.
- Fix only a reproducible build, launch, data-loss, privacy, security,
  accessibility, signing, notarization, or release blocker. Record other
  issues under known limitations for a later version.
- Keep one release candidate at a time. A source or release-input change
  invalidates that candidate and starts its verification again.
- Run the smallest relevant check after a change, then the existing complete
  gate once at the milestone boundary.
- Never infer permission for an external action from progress in this plan.

## Milestone 1 — Prove the current product runs locally

Purpose: establish product health before doing more release infrastructure.

1. Record the clean baseline, local Xcode/Swift/XcodeGen versions, disk space,
   and current model-cache state.
2. Run the existing Package tests and App unit tests without UI automation.
3. Build the unsigned Debug app outside the repository.
4. Launch that exact build without using the XCUITest path that previously
   terminated the Codex host.
5. Exercise the minimum real user journey: onboarding, the `base` / Fast model
   download/load, microphone recording, Raw transcription, Copy Only, and
   History recovery after quitting and reopening the same build. Guarded
   Automatic Paste belongs to the later permission/delivery qualification and
   does not block this first product-health decision.
6. If the live journey fails, stop release work and fix only the reproduced
   blocker; repeat this milestone.

GO: the same external Debug build loads `base`, captures real microphone input,
produces a non-empty Raw transcript, completes Copy Only, and recovers the
History entry after quit/relaunch. Test output and build products remain
outside Git.

NO-GO: any required step fails. Pause GitHub, toolchain-lock, signing, and
publication work; fix only the reproduced product blocker and repeat this
milestone.

## Milestone 2 — Remove release prerequisites and create one candidate

1. Obtain separate approval for the private GitHub repository and first push.
2. Probe the approved `macos-26` arm64 runner and commit the exact toolchain,
   XcodeGen, generated Info, and nested-component lock data.
3. Confirm a usable Developer ID Application identity, Apple team, private key,
   and notary-profile path; confirm access to a second physical supported Apple
   Silicon Mac, preferably covering macOS 14.
4. Run the existing complete local/CI verification and unsigned package smoke
   from one clean commit.
5. Generate the schema-valid exact-commit candidate and its hash-bound
   automated evidence.

Exit: one clean candidate commit passes the locked automated gates. No signing,
Apple upload, public visibility change, or release publication has occurred.

## Milestone 3 — Qualify, sign, notarize, and verify the final DMG

1. Run the real model, permission, dictation, delivery, History, provider,
   documentation, accessibility, and state checks as grouped user journeys.
   Record every existing matrix row without treating it as a separate project.
2. Fix only release blockers; any source fix returns to Milestone 2.
3. Build and sign the exact candidate inside out with Hardened Runtime and
   secure timestamps; create and verify the signed pre-staple DMG.
4. Generate the artifact-scoped notarization request. Submit it only after a
   separate one-use approval for the exact commit, team, and DMG SHA-256.
5. Review the complete Apple result, staple and validate the accepted DMG, and
   record its immutable final SHA-256.
6. Complete quarantined local Gatekeeper checks and the clean-user offline
   checks on the second physical Mac. A transfer to another person requires a
   separate beta-transfer approval.

Exit: the immutable final DMG passes all required local, accessibility,
functional, signing, notarization, and second-Mac gates.

## Milestone 4 — Assemble evidence and publish with explicit approvals

1. Re-run the final public-file, history, privacy, license/model, identity,
   known-issues, support-scope, and documentation review.
2. Produce and verify the exact-commit source archives, release notes,
   `SHA256SUMS`, final DMG, and fixed five-file release inventory.
3. Collect the typed evidence and require the computed status to be `READY`.
4. Present the repository, branch, commit, complete asset inventory, final DMG
   size/SHA-256, test evidence, known issues, and previews to the user.
5. Obtain separate approvals for public visibility and GitHub Release
   publication before performing either action.

Exit: UtterInk 0.1.0 is public with the approved source and verified assets.

## External approval gates

1. Create and first-push the private GitHub repository.
2. Submit the exact signed DMG to Apple notarization once.
3. Transfer a beta DMG to another person, if needed.
4. Change the GitHub repository from private to public.
5. Publish the GitHub Release, remote tag, and assets.
